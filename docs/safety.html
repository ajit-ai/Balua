Balua Safety Analysis

M2 reference. Implementation: safety/analyze.rs:1. Tests: tests/safety_tests.rs:1 (13 tests). Safety runs on lowered MIR when --safety-profile is given; violations block -o (fail-closed).

Profiles

AUTOSAR_CPP14, DO-178C, IEC61508 (case-insensitive), none (no enforcement). Unknown names fail with E_SAFETY_PROFILE. All three real profiles enforce the same three structural rules under different labels — no certification evidence exists yet.

Checks

CodeWhatHow
E_SAFETY_HEAPDynamic-lifetime opsAlloca/HwIntrinsic/MoveToDevice or calls exactly move_to_device|box|alloc|malloc|calloc|realloc (exact match — allocate is clean)
E_SAFETY_RECURSIONDirect + indirect recursionCall-graph reachability over defined functions
E_SAFETY_LOOPUnbounded loopsKosaraju SCCs; cycle with no exit edge. Constant const.N conditions folded (while true unbounded, while false accepted)
E_SAFETY_STACKFrame overflow32 + 4×(params + dest regs) vs #[max_stack(N)], else --safety-stack-limit
E_SAFETY_WCETBound overflow#[wcet_cycles(N)] vs instruction count (crude structural proxy, not a timing model)

Attributes & policy

  • #[max_stack(N)], #[wcet_cycles(N)] collected by parser → FnDecl.attrs → MirFunction.attrs; attribute beats CLI flag. Unknown attributes → W_UNKNOWN_ATTR warning. Attributes on kernels dropped.
  • Enforcement is uniform across Safe/Unsafe/Trusted tiers.
  • Hardware-targeted functions (non-CPU @hw::) are skipped and listed; formal_verification.rs stays emit-only.
  • Clean runs print to stderr: safety profile X: N functions checked (M skipped), 0 violations.

What safety is not

Analysis (real, CPU subset) ≠ policy (same rules, three names) ≠ estimates (rough, not measured) ≠ hardware behavior (nothing executes on accelerators). Stack/WCET numbers are not certification evidence.
