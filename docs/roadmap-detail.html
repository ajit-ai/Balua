Balua — Phase-wise Milestones and Detailed Design Architecture

Local-only plan. Companion to roadmap.rst (ledger) and language.rst (guide). No phase is done until a runnable artifact executes (spec/NFR-roadmap-v2.md:25).

Stubs: LLVM/PTX/SPIR-V/HLS/QASM text, baluald (baluald.rs:22), blpkg ops (builder.rs:17), safety/* flags, std/hal/ffi text, tools/* READMEs, no runtime.

Architecture blueprint

.bl → Lexer → Parser → AST → Semantic(+TypeTable) → MIR → Backend(s) → Link → exe
  1. Spans: Expr::span() (ast.rs:277) defaults collapse TypeTable keys — real per-expr spans before type-directed codegen.
  2. MIR schema: version MirModule/Function/Block/Instruction/Terminator; Phi emitted, never consumed (cranelift.rs:242).
  3. Backend trait: lower -> String (mod.rs:16) lets stubs pass with comments — move to typed artifacts.
  4. One linker: object_emit::build_executable (real) vs BaluaLinker::link (prints, dead) — delete one.
  5. Modules: UseDecl ignored (semantic.rs:97); std/ never read — decide sysroot vs single-file.
  6. Runtime: stay i32-only (document) or add string/array/IO layout.
  7. Safety as MIR passes, not manual bools (misra.rs:12, wcet.rs:17).
  8. Manifest: Balua.toml:1 additive-only versioning.
